# Frontend specification review

- Reviewed: 2026-08-25
- Scope: site shell, Home, Presentation, Articles index, and Article reader

## Result

The five specifications describe one coherent three-destination site. The shell,
Home presentation slice, and Presentation page are ready for implementation
against the existing Presentation API. Articles index and Article reader remain
blocked from production implementation by the intentionally absent Blog API
feed, detail, and safe-content contracts.

## Contract reconciliation

The implemented Presentation API already resolves the frontend questions about
`shortSummary`, `availability`, `currentFocus`, public email and location, and
dimensioned project media. The frontend uses the composite
`GET /api/v1/presentation` read model and preserves API ordering.

The Blog API currently reserves article publishing for a future phase. Until its
public contract is approved, `/articles` and `/articles/:slug` expose neutral
unavailable states and never manufacture article data or reveal private state.

## Prototype direction

The coded prototype follows the user-supplied “Responsive Portfolio Website
Design” source: warm neutral surfaces, deep green and orange accents, Inter UI
copy, Georgia editorial headings, softly rounded controls, and the asymmetric
green focus panel. It supports an explicit persisted theme preference, removes
motion under reduced-motion preference, and starts at a verified 320 px layout.

Development-only presentation and article fixtures make every supplied design
route reviewable while either API is offline. Production builds do not fall
back to fixture data.

## Delivery slices

1. Implemented foundation: Vite, React, TypeScript, routing, TanStack Query,
   shared tokens, route focus/title behavior, shell, not-found route, and tests.
2. Implemented first data slice: Presentation API boundary, Home profile hero,
   complete Presentation composition, independent loading/error states, and
   cached footer content.
3. Deferred contract slice: generated OpenAPI client replaces the typed client
   boundary as part of API-client generation automation.
4. Blocked blog slice: article feed, pagination, reader, content security, SEO,
   and article tests begin only after Blog API specs and OpenAPI are approved.

## Remaining decisions

- Confirm the production domain and public email represented by API seed data.
- Decide whether the first release uses project media; the UI does not require
  it and the API can supply it later without a route redesign.
- Approve Blog API feed/detail/content contracts before promoting either
  Articles spec from Draft.
